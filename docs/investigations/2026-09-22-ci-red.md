## 5. What a fix involves, and who has to do it

Three separate items. **Two of them are James's and cannot be done from a session.**

1. **The frontend deploy — JAMES.** `/version.json` on staging is stuck at `8fd6fbd` while
   the backend advances. The frontend build is failing or lagging on Railway. Diagnosing it
   needs the Railway dashboard: build logs for the staging frontend service. This is the
   blocking one — until the bundle deploys, the gate refuses to run and every other fix is
   invisible.

2. **The CI bot credential — JAMES.** `STAGING_CI_BOT_PASSWORD` in GitHub Secrets no longer
   matches the `ci-bot-runtime-editor@bridgeable.internal` PlatformUser on staging. Per
   CLAUDE.md §7, the repair is `provision_ci_bot --ensure` run against staging, which reads
   the stored secret and makes the database match it — nothing printed, nothing typed.
   ⚠️ **No credential value may pass through a session in either direction**, so this is
   handed over rather than attempted.

3. **The TypeScript errors — anyone.** Three named type errors in two test files and one
   preview file. In-repo, no credentials, no dashboard. This is the only one of the three
   that is ordinary work.
